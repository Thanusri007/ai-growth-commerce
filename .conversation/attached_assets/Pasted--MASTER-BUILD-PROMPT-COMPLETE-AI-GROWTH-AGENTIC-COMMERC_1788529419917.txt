# 5. CUSTOMER AI SHOPPING AGENT

This is one of the most important features.

The AI assistant MUST actually work.

Do NOT implement a fake chatbot where predefined text is returned regardless of the user's request.

Architecture:

USER MESSAGE
↓
CUSTOMER AI UI
↓
SERVER API
↓
AI SERVICE
↓
PRODUCT SEARCH / BUSINESS LOGIC
↓
STRUCTURED RESULT
↓
CUSTOMER UI

The AI must understand natural-language shopping requests.

Example:

User:

"I need a laptop for coding under ₹80000."

The system must:

1. understand category = laptop
2. understand use case = coding
3. understand budget = ₹80,000
4. search the real product dataset
5. filter relevant products
6. recommend suitable products
7. explain the recommendation
8. identify a possible upsell
9. identify useful cross-sells
10. allow the user to view/add products

# 14. PAYMENT SAFETY

THIS IS CRITICAL.

The AI must NEVER autonomously charge the customer.

Payment flow:

CART
↓
CHECKOUT
↓
SERVER CALCULATES TOTAL
↓
PAYMENT CONFIRMATION REQUESTED
↓
CUSTOMER EXPLICITLY CONFIRMS
↓
POLICY ENGINE
↓
RAZORPAY TEST MODE
↓
PAYMENT VERIFICATION
↓
ORDER CREATION
↓
AUDIT LOG

Never trust a price or total generated by the LLM.

The server/database must calculate the amount.

---

# 15. POLICY ENGINE

Create a deterministic policy engine.

Before financial actions verify:

* explicit confirmation
* valid cart
* valid products
* correct server-side amount
* action permission
* merchant policy
* agent permission
* transaction limits

If validation fails:

BLOCK THE ACTION.

Return a clear reason.

Example:

"Payment blocked because explicit customer confirmation is required."

The LLM must not be able to bypass the policy engine.
